# Surf Ace requirements

`DESIGN.md` is normative. Code changes must satisfy its requirements; agents must not edit a requirement to make existing code conform.

Any future change to normative `DESIGN.md` text requires Mike's explicit ruling, named in a separate specification PR. Reviewers reject normative specification edits bundled with code changes. The v0.2.4 restoration of the fleet-unique pane number invariant is authorized by Mike's October 1 ruling and receives the release's one final integrated review.

When Mike approves an exact client change for merge and install but reserves in-use verification for himself, complete the authorized build and installs with checks for artifact identity, version, health, state preservation, and rollback behavior required by the product. Then report the exact installed targets as **READY FOR MIKE TO TRY**. Keep actual terminal fit, clipping, flashes, latency, and other live-use behavior unaccepted until Mike reports it. Do not make an agent-run live session or a ttyd/xterm test a pre-install or post-install gate under that handoff. Keep every unrelated merge, server deployment, security change, and host action within its own approval scope.

For every Surf Ace test or delivery gate, identify the business behavior or `DESIGN.md` requirement it checks. Delete checks that exercise neither, and do not write, install, or require new unrelated checks. Retain the relevant assertions of a mixed check and remove the rest. Classify source tests, CI, private diagnostic fixtures, packaging checks, and review conditions by what they prove, regardless of whether they use mocks, static analysis, integration, or a device. A fixture's success does not establish product acceptance unless it actually exercises the promised behavior. Do not invent a requirement to retain a check. A local process preference, including reviewer harness choice, cannot block delivery by itself. Preserve external access and resource refusals and checks that protect specified product state or identity; this rule grants no new device, registry, release, or security authority.
